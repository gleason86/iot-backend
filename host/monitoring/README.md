# Ryzen service-health evaluator (household observability M3, staged 2026-09-16)

`service_health.ps1` is the Windows PowerShell 5.1 port of
`threadripper/scripts/monitoring/service_health.py` (the CONTRACT.md table says
`service_health.py`; the Ryzen Python install is per-user, so the virtual service
account `NT SERVICE\telegraf` cannot run it — PowerShell 5.1 is the only interpreter
available to that identity). It reads the same version-1 manifest schema
(`../../config/monitoring/dependencies.json`, evaluator worker) and emits the identical
line protocol: `service_health`, `service_check`, `service_dependency` with
`host=ryzen observer=ryzen`, fields `state_code impact_code age_seconds reason
source_timestamp`, ordinal-sorted tags/fields, same escaping. **Staged and unapplied**:
it becomes live when `../telegraf/install-telegraf.ps1 -Mode Apply` deploys it to
`C:\ProgramData\telegraf\monitoring\` and Telegraf runs `exec\service-health.ps1`.

| Check type | Probe | Notes |
| --- | --- | --- |
| `http` | `HttpWebRequest`, no redirects, no proxy, bounded body | allowlist `http_hosts`; `json_contains` supported |
| `tcp` | `TcpClient` connect + close | allowlist `tcp_hosts` |
| `scheduled_task` | `Get-ScheduledTask` + `Get-ScheduledTaskInfo` | allowlist `scheduled_tasks`; keys `task`, `task_path` (`\`), `expect_result` (0), `max_age_seconds`, `expect: scheduled|disabled`. Missing → unknown `task_missing`; Disabled (expected scheduled) → failed; Running/queued → unknown; never ran (1899 sentinel or 0x41303) → unknown; result ≠ expected → failed `result_N` (source = LastRunTime, no last-success); older than `max_age_seconds` → failed `overdue` |
| `file_mtime` | `Get-Item` LastWriteTimeUtc, reparse points rejected | allowlist `file_paths` |
| `disk_free` | `System.IO.DriveInfo.AvailableFreeSpace` | allowlist `disk_paths` (`C:/` accepted); capped at degraded like the original |
| `windows_service` | `Get-Service` | allowlist `windows_services`; `expect: Running|Stopped` |
| `docker_container` | **not probed** (D11: no `docker-users` grant) | `service_check` row code 3, reason `docker input omitted (D11)`, flagged unprobed |
| `derived` / any check with `probe_from` ≠ `ryzen` | not probed (household evaluator) | code 3, reason `derived:<rule>` / `delegated:<prober>` |
| `none` | declared only | as the original |

Unprobed outcomes are rendered but never counted when a service has any probed
check (so `influxdb` = healthy from its HTTP check even though its container check
is omitted); a service whose checks are all unprobed is unknown, and as an upstream it
is treated as `unverified:<id>` (no unknown propagation), whatever its `unprobed`
flag says for the household evaluator. The evaluator row reports
`unprobed_checks=N`.

Differences from the Python original that are visible in the data: the reason charset
additionally allows `()`; failure type names are .NET's (`WebException`,
`SocketException`) instead of Python's (`URLError`, `OSError`); probes run
sequentially under the `budget_seconds` deadline (no thread pool in PS 5.1).

## Commands

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File service_health.ps1 -SelfTest
powershell -NoProfile -ExecutionPolicy Bypass -File service_health.ps1 -Command validate -ManifestPath ..\..\config\monitoring\dependencies.json
powershell -NoProfile -ExecutionPolicy Bypass -File service_health.ps1                       # evaluate the real manifest to stdout
powershell -NoProfile -ExecutionPolicy Bypass -File service_health.ps1 -OutFile out.lp -Now 1789511726
```

`-SelfTest` (run non-elevated 2026-09-16, 23 checks PASS): pass 1 swaps the probe layer
for deterministic fakes at a fixed `-Now`, evaluates `tests\fixture-manifest.json` and
compares every line with `tests\expected.lp` after normalizing only the trailing
timestamp and `duration_ms`; pass 2 runs the real probes on the same fixture (existing
task and service names read-only, `127.0.0.1:1` as a closed port, `hs-selftest-missing`
as a missing task/service) and checks structure only, printing the live output.
`-WriteExpected` regenerates `expected.lp` after a deliberate change (review the diff);
`expected.lp` is generated by the code under test, so it is a regression guard. The
oracle is `-CrossPort`: `homeassistant/host/monitoring/tests/test_cross_port.py` renders
`tests\cross-port-manifest.json` with both ports (same `_fakes`, same `-Now`) and
requires identical output line for line (passes on 2026-09-16).

Live findings baked into the fixture: `com.docker.service` is Stopped/Manual on this
host while the Engine (29.8.0) runs under the user's Docker Desktop session, so a
`windows_service` check on it reports `service_stopped` although Docker works — do
not use it as evidence that Docker is down.
